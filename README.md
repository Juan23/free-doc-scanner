# Free Doc Scanner

A lightweight, free document scanner for iOS and Android. Scan a document and save it to your phone as a PDF, as JPEG images, or both.

## Features

- Edges are detected and the page is cropped and straightened automatically. The app has its own camera screen, the same on iPhone and Android: line the page up (the blue outline follows the page it finds), tap the shutter, then check or drag the corners and choose Next page or Done.
- Multi-page capture and retakes.
- Choose pages to save: tap Select on a scan and pick pages; Save or filter then offers Save as PDF, Save as JPEG or a filter for only those pages, saved in page order.
- Filter for new scans (Clean, Normal by default): Clean whitens the paper and removes shadows, tint, specks and faint creases from each new scan, keeping the writing, and whitens table showing past bent or curled page edges. Light keeps faint pencil and faded print; Strong wipes more. Grayscale cleans to grey, and Original keeps the photos. The last filter you pick on a scan's page becomes the one for new scans.
- Change a saved scan's filter at any time: tap a page, then pick a filter under it ("Use on all N pages" applies it to the whole scan), and each later change starts from the page's untouched photo, so changes never stack.
- Upright pages: a page of text scanned sideways or upside down is turned upright when the app can tell which way is up, whatever the filter, and Rotate in the page editor turns it by hand.
- History: every scan stays in the app, so you can add pages to it later or save it again.
- No accounts, no sign-up, no ads.
- No cloud sync and no network use.

## Privacy

Scanning and saving happen on your phone. The app makes no network requests. It asks for the camera when you scan. On iPhone it also asks for permission to add photos, never to read them. On Android 13 and later it asks for nothing else; older Android versions show the system storage prompt the first time you save JPEGs. Scans are kept inside the app until you delete them; deleting a scan leaves files you already saved untouched. On Android the app's scans are left out of Google's device backup. On iPhone, the phone's own iCloud Backup, if you have it turned on, includes the app's scans like any other app's data.

## How saving works

- **Save PDF** builds one PDF from all the scan's pages, opens the system folder picker and writes `Scan YYYY-MM-DD HH.MM.pdf` to the folder you pick, for example Files on iPhone.
- **Save JPEG** saves each page (`… p1.jpg`, `… p2.jpg`) to Photos on iPhone or Gallery on Android.

## Requirements

- The iOS Simulator has no camera, so scanning on iOS needs a real iPhone. An Android emulator can run the camera screen, but its camera saves black photos.

## Build and run

You need Node, Xcode with CocoaPods for iOS, and a JDK 17 and the Android SDK for Android.

Install dependencies:

```bash
npm install
```

iOS:

```bash
npx expo run:ios --device
```

Android:

```bash
export JAVA_HOME="$(/usr/libexec/java_home -v 17)"
export ANDROID_HOME="$HOME/Library/Android/sdk"
npx expo run:android --device
```

The `ios/` and `android/` folders are generated by these commands and are git-ignored. Change native settings in `app.json`, not in those folders.

## Release builds

- **Android:** release builds are signed with the upload key when `~/.gradle/gradle.properties` has `FDS_UPLOAD_STORE_FILE`, `FDS_UPLOAD_STORE_PASSWORD`, `FDS_UPLOAD_KEY_ALIAS` and `FDS_UPLOAD_KEY_PASSWORD` (see `plugins/withReleaseSigning.js`); otherwise they use the debug key. Build the bundle with `cd android && ./gradlew bundleRelease`.
- **iOS:** archive with `xcodebuild … -configuration Release archive`, then export and upload with `xcodebuild -exportArchive` and `method` `app-store-connect`. Two things matter on this setup:
  - The Apple Distribution certificate must be in the local keychain.
  - `/usr/bin` must come first on `PATH` during export, because Homebrew's newer `rsync` breaks Xcode's packaging step.
- Bump `android.versionCode` and `ios.buildNumber` in `app.json` for every store upload.

Store images live in `store/`.
